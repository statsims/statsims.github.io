Why Compare on the Same Data

  • k-Means assumes round, similarly-sized clusters — try the elongated or two moons scenario to watch it fail.
  • DBSCAN handles odd shapes and noise but struggles when clusters have different densities.
  • GMM generalizes k-Means with elliptical, soft-membership clusters.
  • Hierarchical needs no upfront k — you choose the cut afterward.

The Core Idea

  • Clustering finds structure with no labels. Every method here groups points using only their coordinates.
  • Every algorithm encodes an assumption about what a "cluster" looks like — round, dense, elliptical, or hierarchical.
  • There is rarely one true k. Cluster Validation gives you evidence, not certainty.

Full Reference

Core Concepts

Clustering groups observations by similarity with no target label to predict against — it is unsupervised. Every method here needs a notion of distance between points (see the Distance Metrics tab).

Hard vs. soft assignment: k-Means, Hierarchical, and DBSCAN each give every point exactly one cluster. GMM gives each point a probability of belonging to each cluster.

No ground truth. In real use there are usually no true labels to check against — the Cluster Validation tab shows how to judge cluster quality from the data alone.

k-Means

Alternates assign (each point to its nearest centroid) and update (each centroid to the mean of its points) until centroids stop moving. Minimizes inertia (total squared distance to assigned centroid), but only finds a local optimum — the result depends on the random starting centroids, so real implementations run several restarts and keep the best.

Assumes: round, similarly-sized, similarly-dense clusters, and that Euclidean distance is meaningful for your features (scale your data first if features are on different units).

Hierarchical Clustering

Builds a full tree (dendrogram) bottom-up by repeatedly merging the two closest clusters. Single linkage (nearest point) can chain long, straggly clusters together. Complete linkage (farthest point) favors compact, evenly-sized clusters. Average linkage is a middle ground.

No k is chosen upfront — you cut the finished tree at whatever height gives you the number of clusters you want, which is useful when you're not sure how many groups to expect.

DBSCAN

A point is core if at least minPts points lie within radius eps of it. Clusters grow by chaining together density-reachable core points; border points are within eps of a core point but aren't core themselves; anything else is noise.

Needs no k and finds arbitrarily-shaped clusters, but a single global eps struggles when clusters have very different densities — try the "Varying density" scenario.

Gaussian Mixture Models (GMM)

Fits k elliptical Gaussian components via Expectation-Maximization: the E-step computes each point's probability of belonging to each component (soft "responsibility"); the M-step re-estimates each component's mean, covariance, and weight as a responsibility-weighted average. Log-likelihood increases every iteration until convergence.

Generalizes k-Means — a GMM with equal, spherical, fixed covariance and hard assignment reduces to k-Means. The covariance matrix lets each component stretch and tilt to fit elongated clusters that defeat k-Means.

Distance Metrics

Euclidean: straight-line distance. The default for most clustering methods; sensitive to feature scale.

Manhattan: sum of axis-aligned steps ("taxicab" distance). Less sensitive to outliers in any single dimension than Euclidean.

Cosine: measures the angle between two vectors from the origin, ignoring magnitude entirely. Useful when direction matters more than scale (e.g. text/word-frequency vectors), but only meaningful relative to a meaningful origin — center your data first if "direction" isn't naturally defined.

Cluster Validation

Silhouette score s(i) = (b(i) − a(i)) / max(a(i), b(i)), where a(i) is the mean distance to other points in the same cluster (cohesion) and b(i) is the mean distance to the nearest other cluster (separation). Ranges from −1 (likely misclassified) to +1 (very well matched); near 0 means the point sits on a boundary.

Elbow method: inertia always falls as k grows (more clusters can only reduce within-cluster spread) — look for where the drop stops being steep, not for a global minimum.

Neither method proves a "true" k exists — on genuinely unstructured data (try "No real structure") every k will score poorly, which is itself informative.

Choosing Among These Methods

Know roughly how many groups
k-Means or GMM — fast, and GMM handles elliptical/overlapping clusters better.
Unsure how many groups
Hierarchical — inspect the dendrogram, then decide where to cut.
Odd shapes, expect outliers
DBSCAN — no roundness assumption, and it explicitly flags noise.
Need a data-driven k
Cluster Validation — sweep k with the elbow and silhouette curves.
